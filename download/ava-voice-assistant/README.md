# آوا — دستیار صوتی ویندوز (AVA Voice Assistant)

نسخه **۰.۴۶.۰-بتا (مغز جدید کلمهٔ بیدارباش: تطبیق آوانگار سه‌لایه + ویکورد قابل تغییر)** دستیار صوتی ویندوز، ساخته‌شده با **Electron** — برای اولین بار یک موتور تشخیص گفتار **۱۰۰٪ داخل ویندوز** دارد (sherpa-onnx + Whisper int8): بدون اینترنت، بدون فیلترینگ، بدون کلید، بدون DNS — و تمام پیام‌های «DNS/فیلترشکن» از رابط کاربری حذف شده است.

> در نسخه ۰.۴۶.۰ — مغز بیدارباش + فرمان‌پذیری لاگ‌محور (خواستهٔ کاربر: «این کلمه ویکورد وقتی من میگم خیلی سخت متوجه میشه چون داره از آفلاین استفاده می‌کنه — دقت نسخهٔ آفلاین برای ویکورد بهترش بشه» + «خودت از طریق لاگ نگاه کن»):
> 1. **موتور سه‌لایهٔ بیدارباش (voiceWake.js — معماری جدید):** لاگ واقعی v0.45 نشان داد whisper-base روی «آوا»ی کوتاه «او با / اوه با / حو با / آبا / اوبا / اوربا / ava / Aba» می‌نویسد و موتور قبلی (یک مجموعهٔ ثابت) تقریباً هیچ‌کدام را نمی‌گرفت. حالا تطبیق **آوانگار** است، نه دیکشنری: اسکلت آوایی هر جمله ساخته می‌شود (واحد لب‌سانیِ و/ب/ف/پ = منبع اصلی خطای whisper روی «آوا»، حذف ه/حِ بلعیده، فروپاشی تکرارهای مجاور) و با اسکلت کلمهٔ هدف مقایسه می‌شود. لایه ۱ (دقیق: آوا/اوا/آبا/اوا جان/ava) و لایه ۲ (آوانگار: او با، اوه با، حو با، اوبا…) بیدارِ فوری؛ لایه ۳ (تک‌تکه‌های سخت مثل «پاو با/باو باو/orba») همان برش صوتی را برای تأیید به موتور ابری می‌دهد (سقف ۸ثانیه + امضای برش) و **قاعدهٔ تکرار**: دو نامزد در ۱۲ ثانیه = کاربر دارد صدا می‌زند → بیدار. آغاز صدا هم حالا با ۱۷۰ms پیش‌نواز برش می‌خورد تا حرف اولِ «آوا»ی نرم دیگر قربانی VAD نشود.
> 2. **محافظ بیدارباشِ کاذب:** «او / اوه / هوا / باور / بابا / ابر / ابان / آباد» و نویزِ «صول/[صحر]/"Q"/از از از» (که در لاگ قبلی سیل می‌ساختند) — هرگز بیدار نمی‌کنند؛ مسیر ه-دار فقط برای نام‌های ≥۴ نویسه باز است.
> 3. **«آوا»ی تنها فرمان نیست:** در لاگ واقعی، شنیدنِ فقط «آوا» به Gemini فرستاده می‌شد و جواب بی‌ربط می‌آمد. حالا گفتنِ فقط اسم = «بله؟» + باز شدن گوش دادن، با صفر تماس شبکه.
> 4. **ویکورد قابل تغییر (صوتی و UI):** «میتونم ویکورد رو تغییر بدم» حالا واقعاً ممکن است — چه از تنظیمات (ورودی «کلمهٔ بیدارباش») چه با فرمان صوتی از مسیر AI (act جدید `set_wake_word`)؛ همهٔ لایه‌های تطبیق فوراً روی کلمهٔ جدید می‌روند و برای هر کلمه‌ای (مثل اسم خود کاربر) آوانگارِ عمومی کار می‌کند.
> 5. **«سرچ کن X» دیگر عبارت را گم نمی‌کند:** لاگ واقعی — «برو به سایت ایمال سرچ کن موتور» دو بار URLِ بی‌عبارت باز کرد (و آدرس‌های «/جستجو/» ساختگی حتی HTTP 500 می‌دادند). حالا: فرمت بومی emalls (`emalls.ir/?s=…`) + بازساز عمومی URL (`aiUrlWithQuery`) که هر open_urlِ بی‌عبارتِ AI را با عبارتِ استخراج‌شده از جمله بازسازی می‌کند + قانون ۶ صریح در پرامپت (فا+ان): «URL جستجوی درون-سایتی باید خودِ عبارت را داشته باشد».
> 6. **سبک‌سازی لاگ و شفافیت:** سیلِ «wake-always heard: [صول]» (صدها خط بی‌فایده در لاگ کاربر) با لاگِ غیرتکثیری + آمار دوره‌ای ۱۰ دقیقه‌ای جایگزین شد: `wake stats: checks/heard/near/cloud/wakes`.

> در نسخه ۰.۴۵.۰ — بازنگری سرتاسری منطق (خواستهٔ کاربر: «یک بار از اول شروع کن به بازنگری منطق آوا… یک منطق خیلی خوبی می‌خوام داشته باشه برای جواب دادن همچنین عمل کردن») — ممیزی خط‌به‌خط کل زنجیرهٔ «شنیدن → فهمیدن → تصمیم → عمل → جواب دادن» و رفع ریشه‌ای ایرادهای سیستمی:
> 1. **نیت «بستن» (قرینهٔ باز کردن):** «یوتیوب رو ببند» فقط واژهٔ یوتیوب را می‌دید و یوتیوب را **باز** می‌کرد! حالا فعلِ بستن/خاموش/قطع/استاپ یک نیت واقعی است (yt_close): پنجرهٔ یوتیوب آوا بسته می‌شود، وگرنه ویدیوی شناور، وگرنه پاسخ صادقانهٔ «چیزی باز نیست». «موزیک رو قطع/ببند» هم دیگر صفحهٔ موزیک را باز نمی‌کند — مکث می‌شود.
> 2. **پاسخ صادق در شکست:** ریشهٔ دروغِ پاسخ‌دهی این بود که متن موفقیت («کروم باز شد») قبل از اجرا ساخته می‌شد و نتیجهٔ واقعی نادیده می‌ماند. حالا اگر عمل واقعاً انجام نشود، آوا نام همان کارِ ناموفق را می‌گوید («باز کردن کروم انجام نشد») — در اجرای قوانین، در نگاشت کش‌شدهٔ AI و در خطای اجرا.
> 3. **موزیکِ آگاه‌به‌آهنگ:** «آهنگ شادمهر رو پخش کن» قبلاً هرچه در پلیر بود را پخش می‌کرد و می‌گفت «پخش می‌کنم»! حالا اسم خواسته‌شده از جمله جدا می‌شود؛ در کتابخانهٔ محلی هست → همان پخش می‌شود؛ نیست → درخواست به هوش مصنوعی می‌رود (پخش از یوتیوب)؛ بدون AI → صادقانه راهنمایی می‌کند. + فیکس ریشه‌ای: `\s` داخل رشتهٔ JS به «s» تبدیل می‌شد و «آهنگ رو نگه دار» هرگز مکث موزیک نمی‌شد.
> 4. **دروازهٔ فهم-اول وبی:** برای قوانین وب، «برنامهٔ نصب‌شده بودنِ هدف» کافی نیست — «توی تلگرام دنبال پیام بگرد» دیگر گوگل‌سرچ نمی‌شود؛ به AI می‌رود تا باز کردن برنامه یا پاسخ صادق تصمیم بگیرد. + «توی گوگل دنبال X بگرد» جستجوی گوگل است، نه site:google.com.
> 5. **سبک‌سازی RAM — دور ۲:** صفحهٔ chat.z.ai (یک کرومیوم کامل = صدها MB) دیگر در بوت لود نمی‌شود؛ فقط با اولین باز شدن تب «صفحه چت GLM». توکن نشست کش می‌شود تا «چت سریع» و فرمان‌های صوتی بدون لود صفحه کار کنند.

> در نسخه ۰.۴۴.۰ — «فهم-اول» + سبک‌سازی RAM (گزارش‌های کاربر: «خیلی چیزها هست که سرخود تصمیم می‌گیره… چون فقط یک کلمه‌ای که در جملهٔ کاربر هست در کامند هست پس اون رو اجرا می‌کنه… این اشتباهه»، «توی دیوار دنبال موتور بگرد، نره گوگل سرچ کنه… اول تحلیل کنه و واقعاً بفهمه این چیه… اگه نفهمید بده gemini انجام بده کار رو»، «فقط همین یک چیز که من گفتم نیست — هزار مسئله دیگه هست»، «برنامه رم زیادی مصرف میکنه… باید سبک سازی بشه»):
> 1. **لایهٔ «فهم-اول» (voiceUnderstand.js — معماری جدید):** دیگر هیچ جمله‌ای با «یک کلمهٔ مشترک» اجرا نمی‌شود. هر جمله قبل از اجرا **تحلیل ساختاری** می‌شود: فعل (سرچ/بگرد/پخش/باز کن) + **هدفِ درون-جمله‌ای** («توی دیوار…»، «توی سایت X…»، «برو به سایت X») + موضوع. اگر هدف در فهرست‌های محلی حل شود (سایت معروف با جستجوی بومی مثل دیجی‌کالا/آپارات، یا برنامهٔ نصب‌شده مثل تلگرام/استیم) همان مسیر سریع محلی اجرا می‌شود؛ اگر حل نشود (دیوار، شیپور، «همراه من» و هر اسم دیگری در دنیا) **اجرای کورکورانه ممنوع است** — جمله با تحلیل ساختاری و قانون صریح به Gemini می‌رود تا «واقعاً بفهمد» X چیست: سایت است؟ URL جستجوی درون-سایتی واقعی‌اش را می‌سازد (divar.ir/search?q=…)؛ برنامهٔ نصب‌شده است؟ بازش می‌کند؛ نمی‌داند؟ صادقانه می‌گوید. **هیچ اسمی به دیکشنری اضافه نمی‌شود — تعمیم‌پذیر برای هزار مسئله، نه فقط نمونه‌های گفته‌شده.**
> 2. **قانون ۵ هوش مصنوعی:** پرامپت مغز AI حالا ممنوعهٔ صریح دارد: «درخواستِ درون-هدف هرگز به جستجوی عمومی گوگل تبدیل نشود مگر کاربر خودش گوگل را خواسته باشد» + الگوهای URL جستجوی درون-سایتی سایت‌های معروف + فهرست زندهٔ برنامه‌های نصب‌شدهٔ کاربر در زمینهٔ هر درخواست.
> 3. **سبک‌سازی RAM (جدی):** موتور آفلاین Whisper بعد از ۱۰ دقیقه بی‌کاری خودش را تخلیه می‌کند (~۲۰۰MB آزاد می‌شود؛ با هر استفاده شفاف برمی‌گردد؛ حلقهٔ wake-always هرگز نمی‌گذارد تخلیه شود)؛ سقف هیپ V8 برای همهٔ پروسه‌های آوا (js-flags max-old-space-size=512) جلوی رشد بی‌سقف حافظه را می‌گیرد؛ حباب‌های چت از DOM (بیش از ۱۲۰) و تاریخچهٔ چت (بیش از ۴۰ پیام) آزاد می‌شوند تا نشست‌های طولانی حافظه نگیرند.

> در نسخه ۰.۴۳.۰ — بازطراحی سیستم فرمان‌دهی/فرمان‌پذیری (نه فیکس تکی)، یوتیوب داخل خود آوا، کنترل حرفه‌ای پلیرها، مانیتور و صدای قابل‌تغییر (گزارش‌های کاربر: «TTS رو تغییر میدم ولی هیچی تغییر نمیکنه»، «خیلی چیزا رو الکی انجام میده»، «نمیخام دونه دونه فیکس کنی کامند هارو»، «کاربر لینکو کپی نکنه»، «مانیتور خاموش نمیشه»، «با نرم افزار ما نمیشه دید»، «سیستم کنترل خیییلی قوی برای video player ها»، «اسکن اول نرم افزارای سیستمو»):
> 1. **موتور داوری نیت (voiceIntent.js — معماری جدید):** قبلاً «اولین قانون برنده بود» و هر جملهٔ تادهی جای اشتباه می‌افتاد (مثال واقعی لاگ: «توی یوتیوب برام آهنگ شادمهر پلی کن» → پوشهٔ موزیک محلی باز می‌شد!). حالا همهٔ قوانین منطبق امتیاز می‌گیرند: هر فرمان **لنگر** (+۲۶)، **تقویت‌کننده** (+۸) و **ممنوعه** (حذف مطلق) دارد — موزیکِ محلی با «یوتیوب» ممنوع است، «یوتیوب» با «دستورات» ممنوع است و… برندهٔ قاطع اجرا می‌شود و جملهٔ مبهم با «نامزدهای امتیازدار» به هوش مصنوعی می‌رود تا بین دو نیت داوری کند — دیگر اقدام حدسی و الکی وجود ندارد.
> 2. **یوتیوب داخل خود آوا:** پنجرهٔ «Watch» آوا صفحهٔ کامل یوتیوب را باز می‌کند (نه iframe امبدی که می‌گفت «برو توی خودت یوتیوب ببین»)؛ لینک کپی‌شده («این لینک رو باز کن»)، هر لینک ویدیو (watch/shorts/youtu.be/live) و پخش خودکار با صدای کروم واقعی — حتی لینک‌های غیر یوتیوب هم داخل خود آوا باز می‌شوند.
> 3. **ویدیوی در حال پخش، بدون کپی لینک (SMTC ویندوز):** «چی داره پخش میشه؟» دقیقاً می‌گوید چه چیزی در کدام مرورگر/پلیر پخش است؛ «همین ویدیو رو بیار» همان ویدیوی در حال پخشِ هر مرورگری (کروم/اج/فایرفاکس/…) را با جستجوی عنوان داخل یوتیوب پیدا کرده و داخل پخش‌کنندهٔ خود آوا می‌آورد.
> 4. **سیستم کنترل پلیرها (VLC/mpv/PotPlayer/MPC):** اسکن پلیرهای نصب‌شده؛ «با وی‌ال‌سی پخش کن آهنگ X» → VLC با رابط کنترل HTTP باز می‌شود و از آن بعد «پلیر رو پاز کن»، «برو جلو ۳۰ ثانیه»، «فول اسکرین کن»، «صدا زیاد کن»، «پلیر رو ببند» واقعاً کنترل می‌شود (mpv با IPC pipe). یوتیوب داخل VLC/mpv با yt-dlp استریم می‌شود و پت‌پلیر یوتیوب را native می‌فهمد؛ اگر هیچ‌کدام نبود کلیدهای مدیای جهانی هر پلیر/مرورگری را کنترل می‌کنند.
> 5. **مانیتور و اقدامات سیستمی:** «مانیتور خاموش کن» حالا با PostMessageW + SendMessageTimeoutW (امضای x64 درست) فرستاده می‌شود — روش قبلی به پنجرهٔ هنگ‌شده گیر می‌کرد؛ «صفحه رو خاموش کن» هم اضافه شد + **خروج از حساب ویندوز** («از حسابم خارج شو»).
> 6. **صدای آوا واقعاً عوض می‌شود + اسکن بوت:** ریشهٔ «TTS تغییر نمی‌کند» این بود که اِج روی برخی شبکه‌ها بلاک است و بی‌سروصدا گوگل حرف می‌زد — حالا موتورِ واقعاً پخش‌شده اعلام می‌شود («موتور اِج در دسترس نیست — با گوگل پخش شد») و **صدای مذکر «فرید»/مؤنث «دلارا»** قابل انتخاب است (تغییر = نمونهٔ صدای زنده). نرم‌افزارهای سیستم ۶ ثانیه بعد از باز شدن برنامه اسکن می‌شوند (Start Menu + اپ‌های UWP/Store + Steam) تا «فلان رو باز کن» از همان اول آماده باشد.

> در نسخه ۰.۳۸.۱ — بازبینی کامل همهٔ فایل‌ها + فیکس دونه‌دونهٔ باگ‌های واقعی (گزارش کاربر: «ما خیلی باگ داریم»):
> 1. **ربایش‌های فرمان (ریشهٔ «فرمان‌ها کاری نمی‌کنند»):** «صدا رو خاموش کن» دیگر دیالوگ خاموشی کامپیوتر باز نمی‌کرد (میوت می‌شود)، «بیدارم کن» دیگر وضعیت رم نمی‌گفت (یادآوری می‌سازد)، «ساعت ۵ یادآوری بذار» دیگر ساعت را نمی‌گوید، «حساب کن پنج ضربدر هفت» دیگر ماشین‌حساب باز نمی‌کند (محاسبه می‌شود)، «پینگ گوگل چنده» دیگر پنجرهٔ شناور باز نمی‌کند.
> 2. **نرمال‌سازی متن تشخیص گفتار قبل از اجرای همهٔ قوانین:** خروجی whisper حروف عربی (ي/ك) و نیم‌فاصله دارد؛ قبلاً فقط بخشی از مسیرها نرمال می‌شد و «ری‌استارت» و مشابهش بی‌صدا به هوش مصنوعی می‌رفت. حالا dispatch همیشه روی متن یکدست انجام می‌شود. خطای داخلی هم میکروفن را ۴۵ ثانیه قفل نمی‌کند.
> 3. **بیدارباش دقیق‌تر:** «آواز» و «جاوا/java» دیگر بیدارباش کاذب نمی‌سازند؛ ولی دنبالهٔ فرمان بعد از هر واریانت («آوه به علی زنگ بزن») دیگر دور ریخته نمی‌شود و همان‌جا اجرا می‌شود.
> 4. **تایمر و یادآوری:** «تایمر ۲ ساعت» واقعاً ۲ ساعت بود نه ۲ دقیقه؛ «۱ ساعت و ۳۰ دقیقه» هم پشتیبانی می‌شود. فهرست یادآوری‌های ثبت‌شده حالا در تنظیمات › برنامه با حذف تکی/کلی نمایش داده می‌شود.
> 5. **ویدیوی شناور (PiP):** بستن پنجره صدا را واقعا قطع می‌کند (قبلاً موزیک پنهان در بازی ادامه داشت!)، میانبرهای جابجایی بعد از باز/بسته شدن دوباره کار می‌کنند، جستجوی داخل PiP حالا کیبورد می‌گیرد، جای دستی پنجره بعد از ری‌استارت بازیابی می‌شود، دکمه‌های ⏸/🔊 با وضعیت واقعی پلیر همگام می‌مانند، چرخهٔ شفافیت در ۳۰٪ گیر نمی‌کند و خطای «شناور نتیجه‌ها» رفع شد.
> 6. **زیرساخت:** اسکریپت‌های پیشنهادی هوش مصنوعی با کوتیشن دیگر نمی‌شکنند (EncodedCommand)، لینک یوتیوب با «&» خراب نمی‌شود، فایل‌های settings/یادآوری/یادداشت/PiP اتمیک نوشته می‌شوند (کرش = از دست رفتن کلیدها)، کش منفی Gemini از تأخیر ۹ ثانیه‌ای هر فرمان جلوگیری می‌کند، کرش هر پنجره فقط همان پنجره را ریکاور می‌کند، و اشغال میانبر توسط برنامهٔ دیگر لاگ می‌شود.

> در نسخه ۰.۳۸.۰ — «یوتیوب شناور با عبارت» («یوتیوب شناور آهنگ X»)، جستجوی مستقیم یوتیوب («تو یوتیوب X رو سرچ کن»)، دکمه‌های پخش/توقف/بی‌صدا و نوار جستجوی سریع داخل پنجرهٔ شناور، فیلور بی‌صدای زنجیرهٔ Gemini (۴۲۹ محترمانه) و لینک مستقیم یوتیوب → پخش شناور.

> در نسخه ۰.۲۹.۱ — چهار ریشهٔ گزارش کاربر («خطای اسکریپت The term '????' / دیسکورد کلا کار نکرد / اتصال جمینی حتی در تنظیمات ممکن نیست / بیدارباش را روشن کردم ولی کار نمی‌کند»):
> 1. **بمب کامنت پاورشل (ریشهٔ واقعی دیسکورد):** در ava-dc.ps1 یک کامنت C-سبک (`/* ... */`) مانده بود — پاورشل چنین کامنتی ندارد! پارسر قبولش کرد ولی در زمان اجرا کلمهٔ فارسیِ داخل کامنت به‌عنوان **دستور اجرا شد** → «The term '????' is not recognized» (علامت‌های سؤال = متن فارسی در کدپیج کنسول ویندوز) → همهٔ اکشن‌ها بعد از DBG:PROC می‌مردند. حالا کامنت‌ها همه `#`-خطی‌اند، خروجی پاورشل UTF-8 است (خطاها خوانا می‌مانند) و تست جدید اسکریپت را با **پاورشل واقعی اجرا** می‌کند (نه فقط پارس!) تا این کلاس باگ هرگز برنگردد.
> 2. **بیدارباش همیشگی — خاموشی بی‌صدا حذف شد:** اگر بستهٔ آفلاین نصب نبود، سوییچ روشن شما **بی‌صدا خاموش می‌شد** و هیچ‌کس نمی‌فهمید! حالا سوییچ روشن می‌ماند، بستهٔ آفلاین (~۸۰MB، فقط بار اول) **خودکار دانلود می‌شود**، نوار پیشرفت دارد و بعدش هر وقت «آوا» بگویی (حتی وقتی گوش دادن خاموش است) صدای بانمک پخش و گوش دادن شروع می‌شود. میکروفون اشغال باشد؟ ۳۰ ثانیه بعد خودش دوباره تلاش می‌کند.
> 3. **مسیر ابری دوگانه (ریشهٔ «جمینی وصل نمی‌شود»):** selfcheck قبلی فقط TCP را می‌سنجید و «ok» می‌گفت در حالی که TLS همان مسیر ریست می‌شد؛ و فیلترشکن‌های پراکسی‌ساز (v2ray/هیدیفای/وارپ) پراکسی سیستم ویندوز می‌سازند که کرومیوم رعایت می‌کرد ولی ترافیک ابری پروسهٔ اصلی هرگز! حالا همهٔ ترافیک ابری اول از **استک شبکهٔ کرومیوم** (پراکسی سیستم + پین DNS) می‌رود و اگر مرد از مسیر نود (DNS پین‌شده) — و دکمهٔ «تست اتصال جمنای» مسیر برنده، وضعیت HTTP و راهنمای دقیق فارسی نشان می‌دهد.
> 4. **زنجیرهٔ هوش مصنوعی دروغ نمی‌گوید:** نتیجهٔ ناموفقِ `{ok:false}` مثل جواب موفق حساب می‌شد — یعنی اگر جمنای در دسترس نبود، GLM/سایر موتورها **هرگز امتحان نمی‌شدند** و لاگ هم «ai Gemini ok model=?» دروغین می‌نوشت! حالا فقط جواب واقعاً موفق زنجیره را جلو می‌برد؛ جمنای از کار افتاد؟ GLM (z.ai) همان لحظه مغز دستیار می‌شود. برای فرمان‌های غیرپیش‌فرض هم همیشه هوش مصنوعی تحلیل می‌کند و با پروتکل اجرای عملی (باز کردن برنامه/سایت، صدا، دیسکورد، یادآوری و…) نتیجهٔ واقعی می‌دهد.

> در نسخه ۰.۲۹ — دیسکورد UIA-اول + بیدارباش همیشگی + تست جمنای:
> 1. **اکشن‌های دیسکورد واقعی شدند:** میوت/دی‌فن/قطع/جواب/رد تماس با **UI Automation** دکمهٔ واقعی پنل حساب دیسکورد را به نام دقیق پیدا و می‌زند (بدون دزدیدن فوکوس)، وضعیت را می‌فهمد (از قبل میوت بود؟ صادقانه می‌گوید) و نتیجهٔ واقعی برمی‌گرداند — دیگر «میگه انجام دادم ولی کاری انجام نشده» نیست. «ان میوت/وصل کن میکروفون» هم unmute واقعی است.
> 2. **بیدارباش همیشگی (Siri-وارد):** میکروفون باز می‌ماند، VAD تطبیقی فقط وقت حرف‌زدن CPU می‌گیرد، برش صدا داخل ویندوز با Whisper آفلاین بررسی می‌شود و «آوا» = صدای بانمک + جلسهٔ گفتگو.
> 3. **تست اتصال جمنای در تنظیمات + آدرس رلهٔ شخصی (gemBase)** برای دور زدن محدودیت سرزمینی گوگل.
> 4. **پروتکل intent هوش مصنوعی** پوشش کامل دیسکورد گرفت (unmute/deafen/answer/decline) — «به علی زنگ بزن و بعد میوت کن» یک‌جا اجرا می‌شود.

> در نسخه ۰.۲۸.۱ — ریشهٔ خطای پاورشل ava-dc.ps1:193 char:34 (گیومهٔ کج U+2019 جداکنندهٔ رشتهٔ پاورشل بود → کل اسکریپت پارس نمی‌شد → همهٔ فرمان‌های دیسکورد مرده) + نمایش پیام واقعی خطا به‌جای فقط شمارهٔ خط.

> در نسخه ۰.۲۸ — جلسهٔ گفتگو Siri-وار (یک «آوا» = ۹۰ ثانیه بدون تکرار اسم + صدای بانمک)، باز کردن مستقیم سایت‌های معروف («برو به سایت دیجی کالا»)، دروازهٔ فرمان‌های تلفنی دیسکورد، و UX کلید Gemini.

> در نسخه ۰.۲۷.۱ — فیکس گزارش کاربر («تایپ می‌کند ولی دوباره می‌رود روی listening و درخواست اجرا نمی‌شود»):
> 1. **ریشه پیدا شد:** در «حالت بی‌دست»، فیلتر کلمهٔ بیدارباش (که پیش‌فرض روشن است) هر فرمانی که با «آوا» شروع نمی‌شد را **بی‌صدا دور می‌ریخت** و مستقیم به گوش‌دادن برمی‌گشت — یعنی دقیقاً همان حس «متن را نوشت، رفت روی listening، اجرا نشد».
> 2. **دیگر هیچ فرمانی بی‌صدا دور ریخته نمی‌شود:** حالا کارت «شنیدم — بی‌اجرا» می‌آید با متن دقیق فرمان و دو دکمه: **«همین حالا اجرا کن»** (همان لحظه اجرا می‌شود) و **«از این به بعد بدون آوا»** (فیلتر خاموش می‌شود و از آن بعد هرچه بگویی اجرا می‌شود).
> 3. **قفل‌شدگی cmdBusy هم ریشه‌کن شد:** اگر فرمان قبلی وسط اجرا خطا می‌داد، فلگ busy برای همیشه گیر می‌کرد و همهٔ فرمان‌های بعدی ساکت رد می‌شدند — حالا گارد ۴۵ ثانیه‌ای دارد و هیچ‌وقت ابدی نمی‌شود.
> 4. راهنما: اگر می‌خواهی بدون گفتن «آوا» همیشه اجرا شود، در تنظیمات › تشخیص گفتار تیک «کلمه بیدارباش آوا» را بردار (یا از دکمهٔ داخل کارت استفاده کن).

> در نسخه ۰.۲۷ — صدای همیشه-کار (درخواست صریح کاربر: «اصلاً چرا باید برای ارتباط به DNS وابسته باشیم؟ نمی‌خواهم!»):
> 1. **موتور آفلاین همیشه-کار:** بستهٔ متن‌باز **sherpa-onnx** (پروژهٔ k2-fsa، Apache-2.0) + مدل **Whisper base int8** چندزبانهٔ OpenAI — صدای تو کاملاً داخل ویندوز تبدیل می‌شود؛ حتی اگر اینترنت کامل قطع باشد. یک بار از تنظیمات › تشخیص گفتار دانلودش کن (~۲۱۰MB از GitHub؛ فالبک فایل‌به‌فایل از HuggingFace) و برای همیشه خیالت راحت باشد. در زنجیرهٔ «خودکار» اول ایستاده است.
> 2. **موتور وب دقیقاً مثل dictation.io/کروم:** کلیدهای Speech کرومیوم علاوه بر سوییچ‌های خط فرمان، از **متغیرهای محیطی رسمی** (GOOGLE_API_KEY و…) هم ست می‌شوند — همان شنوندهٔ زنده‌ای که در کروم/پیش‌نمایش عالی بود، حالا با هر دو مسیر ثبت زنده می‌شود.
> 3. **صفر پیام DNS/فیلترشکن:** هیچ پیامی دیگر نمی‌گوید «فیلترشکن روشن کن» یا «تنظیمات DNS» — خطاهای شبکه خنثی شده‌اند («چند لحظه بعد دوباره امتحان کن») و جزئیات فنی فقط در activity.log می‌رود. اگر هیچ موتوری جواب نداد، راه‌حل واقعی پیشنهاد می‌شود: «بستهٔ آفلاین را نصب کن».
> 4. **TTS بدون فاصلهٔ بین جمله‌ها:** تکهٔ بعدی صدا هنگام پخش تکهٔ فعلی پیش‌بارگذاری می‌شود (دوبوفری) — مکث بین جمله‌های پاسخ تقریباً صفر شد.
> 5. **نکتهٔ فنی مهم (با تست واقعی ثابت شد):** Electron اجازهٔ external-buffer نمی‌دهد؛ PCM مستقیم از رندرر می‌آید و با تبدیل Int16→Float32 داخلی به موتور آفلاین می‌رسد — تست ۳ بار متوالی در Electron: پایدار، ~۲.۳ ثانیه برای ۳.۷ ثانیه صدا.

> در نسخه ۰.۲۶ — اتصال تضمینی (اگر هنوز «فیلترشکن روشن کن» می‌بینی، این نسخه را نصب کن):
> 1. **دورزدن DNS «همیشه روشن» شد:** در ۰.۲۴ دورزدنِ شکن/الکترو به گزینهٔ `extDns` وصل بود و اگر فایل تنظیمات کاربر `extDns:false` داشت (درست مثل فایل خودتان!) کل دورزدن خاموش می‌شد و همان «اتصال به سرور برقرار نشد» تکرار می‌شد. حالا دورزدن مستقل از هر گزینه‌ای همیشه فعال است؛ فقط کلید اختصاصی `dnsBypass:false` می‌تواند خاموشش کند.
> 2. **لایهٔ فالبک DoH (برای ISPهایی که UDP:53 را می‌بندند):** اگر UDP به شکن/الکترو اصلاً پاسخ ندهد، آوا مستقیم از **DNS-over-HTTPS شکن (TCP:443)** می‌پرسد (RFC 8484 wireformat) — تقریباً هیچ اپراتوری پورت ۴۴۳ را کامل نمی‌بندد. با تست واقعی: UDP مرده → DoH نجات داد (۵۷۲ms).
> 3. **حافظهٔ منفی مدل‌های ۴۰۴:** اگر مدل تایپ‌شدهٔ کاربر وجود نداشته باشد (مثل `gemini-3.5-flash` که در لاگ شما اول زنجیره بود!) دیگر هر بار امتحان نمی‌شود — یک درخواست و چند ثانیه در هر فرمان صرفه‌جویی می‌شود.
> 4. **پیام خطای کارآمد:** «فیلترشکن روشن کن» کافی نبود — حالا خطای شبکه صریح می‌گوید نسخهٔ ۰.۲۶ خودکار DNS را دور می‌زند و اگر نسخه‌ات عقب است باید بروزرسانی کنی؛ در activity.log هم ثبت می‌شود که شکست در «سطح شبکه» بوده و دورزدن فعال بوده یا نه.
> 5. **کارت بروزرسانی هنگام باز شدن برنامه:** بجِ کوچکِ نوار بالا دیده نمی‌شد و کاربر بی‌خبر می‌ماند که نسخهٔ جدید با همهٔ فیکس‌ها منتشر شده! حالا هر بار برنامه باز شود و نسخهٔ جدید باشد، یک کارت واضح وسط صفحه می‌آید با دکمهٔ «همین حالا دانلود و نصب».

> در نسخه ۰.۲۵ — بازسازی کامل مکالمهٔ صوتی (AVE3):
> 1. **دو مسیر موازی در هر جلسهٔ گوش‌دادن:** مسیر زندهٔ وب (همان شنوندهٔ کرومیوم که در کروم/پیش‌نمایش عالی بود) و هم‌زمان **ضبط واقعی PCM از لحظهٔ صفر** با VAD تطبیقی (آستانهٔ شروع حرف برای هر میکروفونی خودش را می‌سازد — ارث فیکس «صدا دریافت نشد»).
> 2. **«گوش دادن دوباره» کامل حذف شد — ریشهٔ «گرفتن صدا»:** قبلاً اگر موتور وب می‌مرد، گوش‌دادن از صفر شروع می‌شد و باید حرفت را تکرار می‌کردی. حالا اگر وب بمیرد، **همان صدایی که از اول ضبط شده** بی‌درنگ به مسابقهٔ موازی ابری می‌رود — هرگز چیزی را تکرار نمی‌کنی.
> 3. **پایان جمله با VAD واقعی (نه منتظر گوگل):** سکوتِ ۱.۲ ثانیه‌ای بعد از گفتار = پایان جمله؛ اگر شنوندهٔ وب متن بدهد همان لحظه تحویل گرفته می‌شود (برش ثابت‌متن ۷۵۰/۱۱۰۰ms فرمان‌های کوتاه — ارث v0.19). بدون گوگل هم ۸ ثانیه سکوت = پایان مودبانهٔ جلسه.
> 4. **مسابقهٔ ابری روی همان یک صدا (سقف ۱۲ ثانیه):** گوگل رایگان/Whisper/GLM/Gemini هم‌زمان همان WAV را می‌گیرند و اولین جواب برنده است (سقف هر موتور ۲۰→۱۲ ثانیه)؛ فیوز و چسبندگی موتور سر جایش است.
> 5. **teardown تمیز با شمارش نسل:** هر رویدادِ در پروازِ جلسهٔ قبلی (onend/onresult/تایمر مسابقه) با شمارش نسل باطل می‌شود — رفتارهای عجیب استارت/استارت سریع ریشه‌کن شد؛ «شنیدم…» لحظه‌ای که صدا شروع شود نشان داده می‌شود.

> در نسخه ۰.۲۰ هوشمندتر:
> 1. **لایهٔ نرمال‌سازی فارسی (الگوی utils.py پروژهٔ مرجع):** همهٔ فرمان‌ها قبل از تحلیل نرمال می‌شوند — ي/ى عربی → ی، ك عربی → ک، اعداد فارسی/عربی → انگلیسی، اعراب و کشیده حذف، نیم‌فاصله → فاصله — دیگر گوگل هرطور که بنویسی قوانین می‌فهمند.
> 2. **اجرای عملی با جمنای (Function Calling — الگوی نسخهٔ قبلی‌ات):** اگر هیچ لایهٔ آفلاین جمله را نفهمید، جمنای می‌تواند مستقیم «کار» بدهد نه فقط حرف: باز کردن برنامه/سایت، صدا (حتی «صدا رو ۳۰ کن»)، پلیر سیستم، موزیک، دیسکورد (تماس/میوت/قطع)، DNS، یادآوری، اسکرین‌شات و… — حتی **چند کار همزمان** («آهنگ بعدی رو پخش کن و صدا رو هم زیاد کن»). اجرای واقعی فقط با کد محلی آوا و لیست سفید بسته انجام می‌شود؛ برای کارهای حساس (خواب سیستم) تأیید کاربر گرفته می‌شود.
> 3. **تماس دیسکورد — دو حالت:** «کمکی (امن)»: فقط صفحهٔ مخاطب با دیپ‌لینک رسمی باز می‌شود و خودت دکمهٔ تماس را می‌زنی — **صددرصد مطابق قوانین دیسکورد**. «خودکار (آزمایشی)»: کلید/کلیک شبیه‌سازی‌شده به پنجرهٔ دیسکوردِ خودت (مثل ماکروهای دسترسی‌پذیری) — هیچ توکن یا API دیسکورد استفاده نمی‌شود (جنس ریسک «سلف‌بات» ندارد، ولی ضمانت کارکرد هم ندارد). از تنظیمات › دیسکورد انتخابش کن.

> در نسخه ۰.۱۹ سرعت:

> در نسخه ۰.۱۷:
> 1. **تشخیص گفتار کلاس AI (الگوی typeo/iotype):** سایت‌های تایپ صوتی حرفه‌ای با مدل هوش مصنوعی ترنسکریپت می‌کنند نه تشخیص مرورگری — آوا هم همین‌طور شد: موتور **Gemini Audio** (صدای ضبط‌شده با کلید جمنای خودت به generateContent می‌رود؛ برای فارسی فوق دقیق) و موتور **Whisper سازگار با OpenAI** (پیش‌فرض **Groq** با whisper-large-v3-turbo — پلن رایگان و سریع‌ترین ترنسکریپت دنیا؛ آدرس OpenAI یا سرور محلی whisper.cpp هم قابل تعریف است). زنجیرهٔ خودکار: وب (زنده) → جمنای → Whisper → GLM → گوگل رایگان — همان یک صدا به همهٔ موتورها می‌رود تا جواب بگیرد.

> 7. **فیکس‌ها:** اکولایزر در حالت عادی کاملاً ثابت است و فقط با دکمه میکروفون حرکت می‌کند؛ باگ پرش/گیر اکولایزر (فراخوانی سنگین getComputedStyle در هر فریم) رفع شد؛ موج کلیک دکمه میکروفون همیشه از **مرکز دکمه** جریان می‌گیرد؛ اورب حالت روز بوردر باریک‌تر با فید رنگ‌ها تا لبه؛ لوگوی بی‌استفاده بالای ستون بقل حذف شد؛ **اسکرول‌بار تم‌دار** جای پیش‌فرض ویندوز؛ ستون بقل با فید در پس‌زمینه ادغام شد؛ «این رو برام تایپ کن» مستقیم حالت تایپ صوتی را باز می‌کند.

> در نسخه ۰.۱۰:
> 1. **فیکس «صدا دریافت نشد»:** موتور وب گوگل حالا با کلید عمومی کرومیوم داخل Electron واقعاً بالا می‌آید (سگ‌بان ۴.۵ ثانیه‌ای + فالبک خودکار). صدای میکروفون **خام و با AGC** گرفته می‌شود (حذف اثرات NS/EC که کلمه‌ها را می‌خوردند)، **آستانه شروع حرف برای هر میکروفون تطبیقی** محاسبه می‌شود (کف نویز محیط)، اگر کمی صدا بود به‌هرحال برای تشخیص ارسال می‌شود و اگر گوگل جواب نداد، **همان صدا به‌صورت WAV به GLM-ASR** هم می‌رود.
> 2. **پیشنهاد شانسی:** به‌جای لیست طولانی فرمان‌ها، هر چند ثانیه یک فرمان پیشنهادی با انیمیشن flip شیشه‌ای عوض می‌شود — کلیک کن تا اجرا شود. فرمان‌های سفارشی هم در همین چرخه می‌آیند.
> 3. **فرم DNS جدید داخل صفحه اصلی:** با فرمان صوتی «تنظیم دی ان اس جدید» همه‌چیز محو و بلور می‌شود و یک کارت شیشه‌ای با انیمیشن اسپرینگ باز می‌شود: اسم + دو آی‌پی + سوییچ «بعد از ذخیره اعمال شود» — Enter ذخیره می‌کند، کنسل/Esc می‌بندد. مدیر کامل DNS فقط از تنظیمات در دسترس است.
> 4. **اعمال واقعی DNS:** فعال‌سازی هر پروفایل (از فرم جدید، مدیر تنظیمات یا فرمان صوتی) با UAC ویندوز مستقیم روی کارت‌های شبکه اعمال و کش DNS پاک می‌شود.
> 5. **تم روشن + دوزبانه:** تم روشن سفید با رنگ‌های بنفش/کهربایی/سرخابی (مثل نقش زمردی در تم تیره) — با دکمه خورشید/ماه نوار بالا یا تنظیمات. کل رابط کاربری و پاسخ‌های آوا فارسی/English می‌شود (شامل زبان گفتار STT).
> 6. **فرمان‌های پاور:** «کامپیوتر رو بخوابون» (sleep)، «کامپیوتر رو خاموش کن» (با مودال تأیید + قابل لغو با «لغو خاموش شدن»)، «ریستارت کن»، «مانیتور رو خاموش کن».
> 7. **دکمه‌های پنجره سمت راست** + انیمیشن‌های حرفه‌ای صفحه اصلی: تیلت سه‌بعدی اورب، موج کلیک، ذرات شناور، اورای گرادیانی چرخان، درخشش عنوان و ورود نرم صفحه‌ها.

خروجی در پوشه‌ی `dist/` ساخته می‌شود؛ آیکون برنامه `assets/icon.ico` است و شورتکات دسکتاپ با نام «آوا» ساخته می‌شود.

## انتشار روی گیت‌هاب + دانلود کاربران از Releases (فقط یک دابل‌کلیک!)

### راه ۱ — فایل جادویی (پیشنهادی)

روی ویندوز، فایل **`runmetocreateexeforyou.bat`** را دابل‌کلیک کن. خودش:

1. پروکسی خراب گیت را پاک می‌کند (درس ارور port 443)
2. remote را چک و اصلاح می‌کند
3. همه تغییرات را کامیت و پوش می‌کند
4. اگر تگ نسخه قبلاً استفاده شده، **خودش نسخه را بامپ می‌کند** (۰.۵.۰ ← ۰.۵.۱) — یعنی دیگر هیچ‌وقت تناقض version/tag پیش نمی‌آید
5. تگ می‌زند و پوش می‌کند ← **GitHub Actions خودش EXE می‌سازد** و در Releases می‌گذارد

### راه ۲ — اسکریپت پاورشل

اسکریپت `push.ps1` همه‌ی کارها را خودکار می‌کند:

- اصلاح خودکار فیلد `repository` در `package.json` از روی remote گیت‌هاب ← رفع خطای معروف `Cannot detect repository by .git/config`
- سینک خودکار ورک‌فلو CI (`.github/workflows/build.yml`) و `.gitignore` به ریشه ریپو
- عدم ترک‌کردن `node_modules` و `dist`
- کامیت (اگر پیام ندهی، تاریخ و ساعت می‌گذارد)، pull و پوش
- با سوییچ `-Release`: تگ‌زدن نسخه از روی `package.json` (مثلاً `v0.3.0`) ← بیلد خودکار نصب‌کننده و انتشار در GitHub Releases

## نحوه‌ی کار کردن پل Electron (برای توسعه‌ی بعدی)

در `preload.js` این API در اختیار UI گذاشته شده (`window.ava`):

```js
ava.window.minimize() / toggleMaximize() / close()      // کنترل پنجره
ava.system.stats() / run(id, arg) / openUrl(u) / saveAudio(buf) / info()
ava.settings.flags() / setAlwaysOnTop(on) / setLoginItem(on)   // تنظیمات سیستمی
ava.updater.check() / install() / setAuto(on) / onStatus(cb)   // آپدیت خودکار
ava.ai.zaiChat({token, messages})                        // چت GLM بدون کلید — با نشست حساب z.ai
ava.ai.chat({base, key, model, messages})                // چت GLM با کلید API (اختیاری)
ava.stt.google({pcm, rate, key?, lang})                  // موتور رایگان گوگل (PCM ۱۶kHz)
ava.stt.transcribe({buf, base, key, model})              // GLM-ASR (اختیاری، با کلید)
ava.custom.run(script)                                   // اجرای فرمان سفارشی تأییدشده
ava.voice.onToggleListen(cb)                             // رویداد میانبر سراسری
```

فرمان‌های واقعی فقط با «شناسه» از فهرست سفید `COMMANDS` در `main.js` اجرا می‌شوند (باز کردن برنامه، صدا، اسکرین‌شات، قفل، جستجوی وب و…)؛ این یعنی امنیت کامل و هیچ تزریق دستوری از لایه UI ممکن نیست.

### اتصال AI بدون کلید — چطور کار می‌کند؟

1. پنل چت، تب «صفحه چت GLM»: یک `<webview>` با `partition="persist:ai"` که `chat.z.ai` را نشان می‌دهد؛ کاربر یک بار لاگین می‌کند و نشست (کوکی + localStorage) دائمی می‌ماند.
2. توکن نشست با `webview.executeJavaScript("localStorage.getItem('token')")` خوانده می‌شود (فقط در حافظه نگه‌داری می‌شود).
3. «چت سریع» و مسیریابی سوالات پیچیده، همان توکن را به هندلر `ai:zaiChat` در پروسه اصلی می‌دهند که با آن `POST https://chat.z.ai/api/chat/completions` را صدا می‌زند (انتخاب خودکار مدل از `/api/models`، پشتیبانی از پاسخ SSE).
4. اگر کاربر کلید API GLM هم داشته باشد (اختیاری)، مسیر رسمی `api.z.ai` به‌عنوان پشتیبان استفاده می‌شود.
5. پاپ‌آپ‌های لاگین (OAuth گوگل و…) داخل برنامه باز می‌شوند؛ بقیه لینک‌ها به مرورگر سیستم می‌روند.

### نقشه راه نسخه‌های بعد

3. **تنظیم دقیق درصد صدا** و کنترل روشنایی.
